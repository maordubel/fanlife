# Integration contract

This is a research delivery, not a deployed database migration. No club was activated and no production file was modified.

1. Start with SUMMARY.json, coverage.json and the club dossier. Every count distinguishes existing data, observations, collision-free candidates, held records and prior research.
2. Match candidates are under integration-candidates/<club>/wave-matches-2026-10-20.json. Their `status: review` means mergeHistorical will currently skip them. Review the pinned source, competition and result interpretation, then assign real reviewer approval. Never forge historical owner approvals. The current merger is lib/clubs/history-wave.ts and currently wires only its explicitly imported waves; copying a file alone does not activate it.
3. Preserve existing IDs, lineup, scorer lists and frozen game prices. Match by date, normalized home/away and score; inspect multiple same-day records and neutral venue reversals. Aggregate finals and shootouts need separate fields and are held by the collector.
4. Resolve player identities using external provider IDs plus DOB/season evidence. Exact names and CamelCase image asset names are candidate links, not certified English names. A squad registration is not an appearance. Season-ending numbers are not continuous club contracts. Coaches must remain outside player pools.
5. Existing player field proposals and issues are attached per club. Enrich the same ID. Preserve multiple spells and raw source positions. Unknown is null, never a guessed year, birth date or match day. Do not derive a career total by adding overlapping season/profile totals.
6. Goal observations establish only the described facts. Replay drafts remain `review`, approximate and not certified playable. Use existing lib/game/replay/truth.ts and goal-wave.ts; validate final contacts, 2–5 action limits, provider action semantics, dated actor pools and original source position envelopes. Do not map deflections/clearances to goalkeeper saves or invent a missing passing origin.
7. Prior research is inherited, including any unresolved credits or original owner approvals. Files without new extraction are inventories, not verified claims. Unopened club folders are staging dossiers. Cross-club mirrored records can overlap CC0 candidates and must be deduplicated before import.
8. Run the repository census/compiler, identity and history conflict checks, focused tests and build after integration. This ZIP's validation confirms dataset shape and provenance references, not historical truth of every inherited record or 99% completeness.

Reproducibility: cc0-source-snapshots contains pinned source bytes; methodology contains the original collector/parser source. These collection scripts refer to the original working layout and require Python/lxml and a FanLife checkout; they are method records, not an installation command. Offline validate_bundle.py runs using the Python standard library from anywhere. No API keys, credentials, node_modules or git internals are included.
