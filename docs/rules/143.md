## 143 · Research reaches a club through the owner's yes, one question at a time (10.11.2026)

Owner: *"two months of daily research and not one new club — why?"*, then *"keep the decision with me, but easy access, click only."* Map: `docs/fanlife/73-research-desk.md`.
1. **Staged material is a club in waiting, not a folder.** A registry club with no repository pack compiles from `research-staging/<id>/` (UEFA's approved ties — rule 102 — plus every batch the owner approved) in `deskProvider`, through the same compiler. Publication is untouched: it opens only through `clubs/open-playable`.
2. **A yes is pinned to content.** `lib/research/staged/model.ts` turns each review file into a batch with a hash; a decision counts only for that hash (`approvedBatchIds`), a changed file waits for a new yes (`staleBatchIds`), a `conflictFree:false` record is never promoted, a promoted one carries confidence ≤2 and `owner · … on the research desk <date>`. Decisions live in durable `research-desk/<id>.json`, written only by `research/desk/decide` from the owner's session, audited before/after.
3. **The desk asks one question per club** (`lib/research/desk-model.ts`): approve the batch that opens most → choose the rival from the clubs met most → open → nothing to do. Every card says what the yes opens, from `research-reports/desk-preview.json` (`npm run research:desk-preview`, daily), recompiled only when the material's hash changed.
4. **A pull grows history, it does not repeat it.** `club:wave` reads the newest `--max`, then `--backfill` ties the wave lacks, then `--refresh` held ties for UEFA's squad details (`squad[]`: pos, born, nat, shirt, height — never guessed); a discovered UEFA id is saved to `ingest.json`; no id is `NO_UEFA_TEAM`, an alarm on the desk until fixed.
5. **The report leads with what needs the owner**, then gates gained this week, then collection health (`research-reports/health.json`: no-UEFA, stalled ≥7 days). A count that does not move for a week is a finding, not a quiet day.
6. **"Open" is the whole club, and it finishes itself.** Owner: *"the full opening — every graphic, the home and inner pages, the shared features with the other clubs; miss nothing; fully automatic."* The click publishes the games at once (`clubs/open-playable`); within the hour `.github/workflows/club-open.yml` reads `research/desk-export` (scheduler secret), runs `scripts/clubs/promote.ts` — pack, ingest + wave-auto moved, every hand-wired list (`resolver-ids`, `providers`, `euro-wave`, LIFE `packs`, `spellings`, fixture teams, social tags, crest from the same open catalogue) — then the generated lists (Rumble freeze, English names, launch defaults), the LIFE stills (`capture-shots.mjs` → `shots-measure.py`), types, the full test suite as CI runs it (a workflow-token push starts no CI), hygiene, provenance and the compile, and merges only when all pass; it reports running/merged/failed to `research/desk/promotion` and the desk shows it ("Try again" re-runs). A new hand-wired per-club list is a new line in `promote.ts` and in its test, or the next opening misses it.
